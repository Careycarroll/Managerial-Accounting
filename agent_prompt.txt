# Managerial Accounting Interactive -- Agent Prompt

You are a code agent for the Managerial Accounting Interactive project. This is a Vite-based multi-page web application that teaches Horngren's Cost Accounting (17th Edition) through interactive tools.

---

## Project Context

Goal: Build a comprehensive interactive learning companion covering all 24 chapters of Horngren's Cost Accounting. Students learn concepts chapter by chapter (Learn section), practice calculations (Practice section), then apply them to real business decisions (Apply section).

Live site: https://careycarroll.github.io/Managerial-Accounting/
Repo: ~/Github Projects/Managerial-Accounting/
Stack: Vite 7, vanilla JS (ES modules), CSS custom properties, KaTeX, vite-plugin-pwa

## Architecture

### Three Sections
- Learn -- 24 chapter pages (pages/learn/ch01.html through ch24.html). Each page: hero, learning objectives, 3-5 interactive tools, show-work panels, key terms panel, chapter complete marker.
- Practice -- Randomized multi-step calculation problems. pages/practice/. Students receive data and must calculate answers step by step with no options to anchor from.
- Apply -- 12 scenario pages (pages/apply/*.html). Each scenario has three depth levels: Concept / Analysis / Simulation.

## Dark Mode Rules

Dark mode toggled via data-theme="dark" on html element. All overrides in css/settings-panel.css.

### Critical Rule: No Hardcoded Hex in JS Output
Always use CSS custom property tokens. Never hardcode hex values in JS-generated HTML.

### Dark Mode Token Reference

    --color-success-bg     dark green bg
    --color-danger-bg      dark red bg
    --color-warning-bg     dark amber bg
    --color-info-bg        dark navy bg
    --color-poor-bg        deep dark red bg
    --color-success        teal text
    --color-danger         red text
    --color-warning        amber text
    --color-poor           bright red text
    --color-info           light blue text
    --color-primary-text   light blue in dark, navy in light
    --color-accent         gold, same in both modes
    --color-gray-50 through --color-gray-900  all overridden in dark
    --color-border         dark border
    --color-card-bg        dark card background

### Inline Script in Every HTML Head

    <script>
      (function(){
        var r = document.documentElement;
        var w = localStorage.getItem('pref-width');
        var f = localStorage.getItem('pref-font');
        var t = localStorage.getItem('pref-theme');
        if (w) r.style.setProperty('--max-width-tool', w + 'px');
        if (f) r.style.setProperty('--font-scale', f);
        if (t === 'dark') r.setAttribute('data-theme', 'dark');
      })();
    </script>

### Simulation Engine
    js/engine/scenario-engine.js    Domain-agnostic state machine
    js/engine/scenarios/breakeven-sim.js  First simulation -- 5 stages, all three answer types

Engine features:
- Three answer types: single-choice (bell curve), multiple-choice (select all), numeric (free entry)
- Answer type randomly selected per stage per round
- Four scoring levels: optimal, acceptable, suboptimal, poor
- Show work panel after every decision via renderShowWork()
- Selection breakdown for multiple-choice with per-option correct/incorrect
- Weight-based debrief rating
- randomizeMetrics() called on every init/reset
- Bell curve option generator -- optimal shifts position, irregular spacing
- Branching via nextStage string or function
- operationType in breakeven sim -- overhead allocation correct answer shifts each round

## Simulation Engine Reference

### ScenarioEngine API
    engine.init(scenarioDefinition, containerEl)  -- load and render first stage
    engine.reset()                                -- re-randomize and restart

### Scenario Definition Format

    export const mySim = {
      id: 'my-sim',
      title: 'Scenario Title',
      randomizeMetrics() { return { ...metrics }; },
      metricDisplay: [{ key, label, format, poorIf? }],
      stages: [ ...stage definitions ],
      reviewChapters: [{ label, href }],
    }

### Stage Definition Format

    {
      id: 'stage-id',
      title: 'Stage N -- Title',
      answerTypes: ['single-choice', 'multiple-choice', 'numeric'],
      context: (state) => '<p>HTML string</p>',
      highlightMetrics: ['key1', 'key2'],

      // Single choice
      generateOptions: (state) => [{ label, sublabel, consequence: (state) => ({ score, narrative, detail, metricUpdates }) }],

      // Multiple choice
      generateMultiOptions: (state) => [{ id, label, sublabel, correct }],
      evaluateSelection: (selected, state, allOptions) => ({ score, narrative, detail, metricUpdates, selectionBreakdown }),

      // Numeric
      numericConfig: (state) => ({ label, unit, min, step, hint, evaluate: (value, state) => ({ score, narrative, detail, metricUpdates }) }),

      // Show work (all types)
      showWork: (answer, answerType, state) => [{ label, formula, values, result, highlight? }],

      nextStage: 'stage-id' | (state) => 'stage-id' | null,
    }

### Score Levels
    optimal    -- weight 1.0 -- green  -- correct answer
    acceptable -- weight 0.6 -- amber  -- reasonable but not ideal
    suboptimal -- weight 0.2 -- red    -- mistake, math does not support
    poor       -- weight 0.0 -- deep red -- harmful, could cause business failure

### evaluateSelection Signature
Always use (selected, state, allOptions) -- third arg is full options array for breakdown construction.
Always extract ids at top: const ids = selected.map(o => o.id);
Always build breakdown from allOptions: allOptions.map(o => ({ label: o.label, selected: ids.includes(o.id), correct: o.correct, reason: ... }))

## Practice Section Design (Planned)

### Concept
Students receive randomized financial data and calculate answers step by step. No options, no tools. Pure calculation practice.

### Practice Engine API (planned)
    engine.init(problemDefinition, containerEl)
    engine.reset()  -- re-randomize and restart from Step 1

### Problem Definition Format (planned)

    export const myProblem = {
      id: 'problem-id',
      title: 'Problem Title',
      difficulty: 'foundation' | 'intermediate' | 'advanced',
      chapters: [3],
      estimatedMinutes: 5,

      randomize: () => ({ ...data }),

      given: (data) => [{ label, value }],

      steps: [
        {
          id: 'step-id',
          question: 'What is the contribution margin per unit?',
          unit: '$ per unit',
          tolerance: 1,
          hint: 'CM = Selling Price - Variable Cost',
          solve: (data, correctPrior) => answer,
          showWork: (data, correctPrior) => [{ label, formula, values, result, highlight? }],
        }
      ]
    }

### Grading
- Tolerance-based: Math.abs(student - correct) <= tolerance
- Correct values carry forward to subsequent steps regardless of student answer
- Hint usage flagged per step -- shown in summary, does not reduce numeric score
- Score: 4/4 Expert, 3/4 Proficient, 2/4 Developing, 1/4 or less Review chapter

### Navigation
- Practice is a first-class nav link: Learn | Practice | Apply | Glossary
- Landing page has three tiles: Learn, Practice, Apply
- Practice index has two sections: Chapter Problems and Cross-Chapter Problems

## Apply Section Design

Each Apply page has:
- Hero with scenario title, chapter badges, depth toggle buttons
- Three div.depth-panel panels -- only active panel visible
- Simulation panel has depth-simulation-wrapper > depth-simulation-container

Depth levels:
- Concept -- 2-3 inputs, single answer, plain-language explanation
- Analysis -- 8-15 inputs, structured comparison table, sensitivity output
- Simulation -- ScenarioEngine driven, sequential decisions, consequence rendering, debrief

Simulation wiring pattern:
    import { ScenarioEngine } from '/js/engine/scenario-engine.js';
    import { mySim } from '/js/engine/scenarios/my-sim.js';
    // In initDepthToggle(), when depth === 'simulation' and simEngine === null:
    simEngine = new ScenarioEngine();
    simEngine.init(mySim, document.getElementById('depth-simulation-container'));
